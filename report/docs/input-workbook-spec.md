# Input Workbook Specification: Month-Wise Task Sheets

## 1. Objective & Design Goals
The monthly input workbook provides an effortless, low-friction entry point for process engineers.
Engineers typically enter tasks right from the shop floor or engineering desk. To maximize compliance and eliminate administrative friction:

1. **No Task Dates:** The month is inherently determined by the active worksheet (e.g., `SEP-2026`, `JAN-2027`).
2. **No Extraneous Fields:** Engineers are **not** asked for descriptions, impacts, categories, statuses, costs, or deadlines.
3. **Dropdown Selection:** The `Engineer` field is picked directly from the Master Data list.
4. **Minimal Input:** The engineer types only the `Task Name`.

---

## 2. Workbook & Worksheet Naming Convention

Each operational month has its own dedicated worksheet tab formatted as `<MMM-YYYY>`:

```
[ JAN-2026 ] [ FEB-2026 ] ... [ AUG-2026 ] [ SEP-2026 ] [ OCT-2026 ] ... [ DEC-2027 ]
```

* Supported Month Codes: `JAN`, `FEB`, `MAR`, `APR`, `MAY`, `JUN`, `JUL`, `AUG`, `SEP`, `OCT`, `NOV`, `DEC`.
* Full Year: 4-digit Gregorian year (e.g., `2026`, `2027`).

---

## 3. Worksheet Column Structure

The monthly input sheet maintains a clean, straightforward structure:

| Column | Header | Data Type | Constraint | Description |
| :---: | :--- | :--- | :--- | :--- |
| **A** | **Task ID** | String | Immutable Unique Key | Generated by system upon row creation (e.g., `SEP-2026-001`). Never modified manually. |
| **B** | **Engineer** | String | Required (Dropdown) | Selected from Master Data (e.g., `Sazzad`, `Rafi`, `Faiyaz`). |
| **C** | **Task Name** | String | Required (Free Text) | The raw title or subject entered by the engineer (e.g., `Compressor Jacket Foil Cutting System Development`). |
| **D** | **Include in Report** | String | Enum (`YES` / `NO`) | Defaults to `YES`. Changing to `NO` excludes the task's slide from the monthly deck without deleting the task. |
| **E** | **Created Timestamp**| ISO Date | System Auto-filled | Timestamp when the entry was first logged. |

## 4. Task ID Specification

Every task row receives a permanent, immutable Task ID generated by the formula:
$$\text{Task ID} = \langle\text{MMM}\rangle\text{-}\langle\text{YYYY}\rangle\text{-}\langle\text{NNN}\rangle$$

* **Examples:**
  * First task of September 2026: `SEP-2026-001`
  * 42nd task of September 2026: `SEP-2026-042`
  * 105th task of January 2027: `JAN-2027-105`
* **Rules:**
  * The Task ID is the **sole synchronization key**.
  * Task names can change or be edited; the Task ID remains fixed.
  * Task IDs are strictly non-reusable within a month.

## 6. Report Inclusion Filtering Logic (`Include in Report`)
* Every new task row defaults to `Include in Monthly Report = YES`.
* When set to `YES`: The task is queued for AI breakdown, slide generation, and inclusion in the final exported PPTX/PDF/HTML presentation.
* When set to `NO`:
  * The task remains intact in the monthly input sheet (preserving historical records).
  * On the next synchronization, its generated slide is removed from the active presentation deck.
  * Re-toggling to `YES` seamlessly restores the slide without re-triggering AI generation if the source hash has not changed.
